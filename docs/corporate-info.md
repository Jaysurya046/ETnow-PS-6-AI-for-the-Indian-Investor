# Corporate Info / Market Signals

The Signal Monitor contains a three-tab official filing panel alongside momentum observations on wide screens. The Research Desk exposes the same panel in its holdings drawer, defaulting to portfolio scope. Filings are displayed independently of AI: they are not automatically inserted into chat prompts or used to infer trading signals.

## API and sources

`GET /api/corporate-info?tab=announcements|actions|results&symbol=RELIANCE`

The default category is announcements and the default scope is the checked-in NIFTY 100 universe. `symbol` accepts one NSE ticker or up to 100 comma-separated tickers, optionally suffixed `.NS`. This permits portfolio stocks outside the index. Invalid categories/symbols return 400. Every response contains `announcements`, `actions`, `results`, `asOf` (ISO UTC acquisition time), and `isStale`; inactive category arrays are empty. Search is client-side.

Official sources, accessed through the existing `lib/nse.ts` browser-header/session-cookie transport:

- [Announcements](https://www.nseindia.com/companies-listing/corporate-filings-announcements): `/api/corporate-announcements?index=equities`, using a trailing 30-calendar-day window.
- [Corporate actions](https://www.nseindia.com/companies-listing/corporate-filings-actions): `/api/corporates-corporateActions?index=equities`, from seven days ago through 90 days ahead. Only EQ-series actions are included.
- [Financial results](https://www.nseindia.com/companies-listing/corporate-filings-financial-results): `/api/corporates-financial-results?index=equities`, requesting `period=Quarterly` and `period=Annual`, merged and deduplicated. The bare endpoint returned an empty array during verification; explicit periods returned records.

`lib/corporate-feed.ts` maps NSE fields and validates required data. Announcement `an_dt` and results `broadCastDate` are parsed as IST, then stored as ISO UTC. Corporate action dates retain their published day labels; absent dates say Unavailable. Financial results derive Standalone/Consolidated from NSE's `consolidated` field. NSE's separate `cumulative` field has a different meaning and is not substituted for consolidation. The interface therefore calls this **Reporting basis** rather than conflating the two concepts.

PDF/XML badges require an actual attachment URL and matching extension. URLs must use HTTPS and an allowed NSE archive/domain; placeholder XBRL paths ending in `/-`, arbitrary hosts and unsafe schemes are rejected. Attachments open separately with `noopener noreferrer`. No filings or attachments are generated by AI. The panel displays exchange subjects, not independently verified explanations of those events.

## Cache, provenance and limits

There are exactly three in-memory cache entries, shared across symbol/search scopes. Each entry normalizes at most 20,000 source rows, coalesces concurrent loads and preserves its last successful snapshot. TTL is 15 minutes on weekdays 09:00–18:00 IST and two hours otherwise, shortened at the next market-window boundary. It uses clock windows, not an NSE holiday calendar. Failed loads back off five minutes and mark the original snapshot stale without replacing its acquisition timestamp. HTTP responses use `Cache-Control: no-store` so intermediary caches cannot conceal stale status.

`lib/data/corporate-info-fallback.json` contains captured NSE records, not illustrative fixtures: 200 announcements, six actions and 188 results from the index universe. It records source URLs, individual capture timestamps, upstream row counts and small raw samples used by regression tests. The root `asOf` is the oldest source acquisition time. Seed data is always stale, even if a checked-in flag is changed. It is a bounded maintenance snapshot, not complete company history. Holdings outside its coverage may have no offline records.

Result feeds can contain old filings. Their broadcast dates remain visible even after a fresh fetch: **Updated** means feed acquisition, not earnings publication date. No new results are inferred from quarter-end or today's calendar. The initial quarterly index snapshot includes older historical results.

The panel polls every minute, while server TTLs govern upstream refreshes; this is periodic cached JSON ingestion, not exchange push streaming. Cookies/cache/history are process-local and restart from the verified seed. NSE may deny requests in some hosting environments. Maintain verified captures and deploy shared durable caching if cross-instance consistency is required.

## UI and verification

Industrial terminal direction, DFII 14: compact filing rows, amber-underlined tabs, IBM Plex typography, signed/numeric date alignment and restrained orange PDF / pink XML badges. Colors are CSS tokens in `app/globals.css`. A scoped grid pairs the panel with market observations above 1500px workspace width; narrower layouts stack. Tab strips scroll inside the panel, long subjects wrap, and file badges remain visible. Arrow keys/Home/End navigate tabs with roving focus. Scope controls expose pressed state and empty portfolios never expand to the index feed.

Standalone panels read validated `etnow.portfolio.v1` storage on mount, focus and cross-tab storage events. The chat drawer receives active symbols directly, so add/remove actions update it immediately. Stored quantities and costs are never sent to the corporate endpoint; symbol scope is sent to this app only, and upstream NSE requests remain shared fixed category queries.

Verification on 24 October 2026: all 45 regression tests, ESLint and the standalone production build passed. Live local API checks returned 974 index announcements, three actions and 191 results with `isStale: false`; counts are observations, not fixed expectations. Tests cover real captured payloads, malformed schemas, duplicate IDs, safe URLs, IST parsing, exact portfolio scope, cache coalescing/backoff and offline snapshots.

Browser checks confirmed all tabs, attachment badges, ticker search, a portfolio scope containing only RELIANCE/KOTAKBANK, and an empty state after removing temporary test holdings. Measured document widths were 369px at a 375px viewport, 1433px at 1440px and 3840px at 3840px. The mobile drawer was contained at 336.67px. Viewport overrides and the test server were reset after verification.
